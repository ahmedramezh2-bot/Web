# HEBRA MASTER PRODUCTION BIBLE

## EXECUTION HIERARCHY AUTHORIZATION

*Documentation only. This document assigns named people to the roles the Production Execution Protocol and AI Development Protocol already defined structurally. It changes no authority rule already established — it closes the staffing gap identified in the Phase Gate Review.*

====================================================

PREAMBLE

The Production Execution Protocol (`docs/bible/22`) and the AI Development Protocol (`docs/bible/15`) both define an Execution Hierarchy and Authority Hierarchy by role, not by person. The Phase Gate Review (`docs/bible/23` §3) flagged this as an operational gap: the hierarchy was aspirational until real people were assigned to it.

HEBRA is built by a solo creator working with AI assistance. This document formalizes that reality inside the existing hierarchy structure rather than inventing a new one — every role defined in `docs/bible/22` §1 and `docs/bible/15` §2 is preserved exactly; this document only fills in who holds each one.

====================================================

A single person moving between roles still owes each role's specific checklist and review discipline; the Constitution Review Protocol's ten Review Stages (`docs/bible/16` §2) are not waived by role consolidation.

====================================================

## 2. WHAT DOES NOT CHANGE

**The AI never owns creative authority.** Restated verbatim from the AI Development Protocol §2 and §4 — Claude Code and Claude, in the roles above, remain assistance and infrastructure roles exactly as defined there. Nothing in this document extends AI authority beyond what AI Development Protocol §3 already grants.

**The AI never overrides the Constitution.** Every Bible in this repository remains binding on both AI roles exactly as it was before this document existed. AI Development Protocol §4's restriction list (never invent lore, history, architecture, visual identity, symbols, or artistic direction unilaterally) applies without modification.

**Human approval remains the final authority.** Ahmed, in whichever human role is relevant to a given decision, holds final sign-off per the Constitution Review Protocol's Approval System (`docs/bible/16` §8). A single person holding all human roles does not collapse the Review Stages into one step — each stage's checklist is still checked, even when the same person checks all of them, because the checklist is what prevents a decision from skipping consideration, not the presence of a second person.

**The Decision Hierarchy is unchanged.** Production Execution Protocol §1's Decision Hierarchy still escalates novel decisions to the Creative Director role and still requires them logged as a documentation amendment before implementation — this document does not shortcut that discipline just because the same person now holds every escalation target.

====================================================

## 3. PRACTICAL CONSEQUENCE FOR REVIEW

Because one person holds every human role, self-review is unavoidable and is explicitly accepted rather than treated as a compliance failure. To keep the Constitution Review Protocol's Review Stages (`docs/bible/16` §2) meaningful under this constraint:

- Every review is still performed against its role's own checklist (per the relevant Bible's Review Checklist section), in writing, not held only as an internal judgment call.
- The AI Research and Implementation Assistant roles are explicitly leveraged as an independent check where useful — Claude and Claude Code do not hold creative authority, but they can and should surface inconsistencies against the Constitution's own written rules (exactly as this session's audits have done), giving the solo human reviewer a second, mechanically consistent pass before sign-off.
- The Constitution Consistency Report pattern (`docs/bible/reports/`) is the standing mechanism for that second pass — future amendments are expected to produce one, not skip straight from change to sign-off.

====================================================

## 4. AMENDMENT

Any future change to who holds a role, or to the role list itself, follows the Camera Bible's own amendment discipline (Camera Bible §26) — logged here, with a stated reason, never changed silently.
